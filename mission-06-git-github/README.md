## Task 6.1 — Basic Git Workflow

| Git operation | What it does |
|---|---|
| Check repository status | `git status` shows modified, staged and untracked files. |
| Stage selected changes | `git add filename` prepares selected changes for committing. |
| Create a commit | `git commit -m "message"` saves staged changes in the repository history. |
| View commit history | `git log --oneline` displays recent commits. |

### Difference Between Staging and Committing

Staging means selecting the changes that I want to include in the next commit. Committing means permanently recording those staged changes in the local Git history.

## Task 6.3 — Pull Request

A branch is a separate line of development that allows changes to be made without directly affecting the main branch.

A Pull Request is a request to merge changes from one branch into another. It allows others to review the changes before they become part of the main project.

Pull Requests are useful because they make collaboration, reviewing and managing changes easier.

## Task 6.4 — Git Command Glossary

| Git command | Explanation |
|---|---|
| `git init` | Initialises a new Git repository. |
| `git status` | Shows the current state of the repository. |
| `git add` | Stages changes for the next commit. |
| `git commit` | Records staged changes in Git history. |
| `git log` | Displays previous commits. |
| `git branch` | Creates or lists branches. |
| `git switch` | Switches from one branch to another. |
| `git push` | Publishes local commits to a remote repository. |
| `git pull` | Retrieves and integrates remote changes. |
